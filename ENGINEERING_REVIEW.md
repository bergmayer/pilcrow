**Original review scope and execution paths.** At the September 4 baseline the project targeted iOS 26.0. The September 7 follow-up below raises the minimum to iOS/iPadOS 27 at the user’s request. It remains an iPhone/iPad application. App and tests use Swift 6; the vendored EditorEngine retains Swift 5. Mac Catalyst, iPad-on-Mac, and visionOS eligibility remain disabled. Signing settings, application identifiers, and dependencies are unchanged. The deployment target was unchanged in the original review; see the September 7 follow-up for the subsequent change. The Xcode project adds the coordinated-access and regression-test sources, removes the unused picker bridge, and updates the renamed destination source.

`PilcrowApp` initializes preferences, templates, and recovery, then creates editor and utility scenes. Each `EditorScene` owns an `EditorSession`; each tab owns its document and primary/secondary pane state. EditorEngine's native buffer is authoritative during editing. `document.text` and `state.text` are debounced snapshots. Save, insertion, close, tab switching, and restoration must reconcile against the live buffer rather than treating these copies as independent editable data.

Opening through Files, recent files, external URLs, and restoration converges on the existing document workflow. Supported content remains plain/source text, Markdown, TeX/Typst, JSON, XML, YAML, HTML, and delimited text, with the existing encoding detection and BOM behavior. Unsupported/binary input and the existing 100 MB document ceiling remain checked. Native UIKit text input, selection, marked text, folding, accessibility forwarding, and undo are retained.

Explicit Save modifies the source. Autosave writes local scratch/recovery files and revisions; it does not silently save over an external document. Recovery metadata retains the source bookmark and encoding. Session background/close persistence commits recovery before recording its references. Closed-window recovery remains a separate, explicit operation. `RevisionStore` remains an actor; source-file coordination is now asynchronous and scoped to each operation.

**Prioritized assessment and implemented fixes.**

1. **Document integrity and asynchronous state transitions — confirmed defects.** The old metadata-based save check had a check-to-write gap and could miss same-size, same-date external changes. File work also occupied the main actor. `CoordinatedFileAccess` now owns security-scoped access, Foundation file coordination, cancellation, and a deadline. Reads, decoding, encoding, validation, and atomic source writes run on the accessor queue. Existing-file saves compare exact original bytes inside write coordination. An explicit Save Anyway authorizes overwrite; ordinary saves reject conflicts. Cancellation before access performs no write; once a write starts, the operation reports its actual outcome rather than implying that cancellation rolled it back.

   A captured `SavedSnapshot` contains the bytes and settings actually written. `DocumentWorkflow` adopts it only into the originating document generation. Edits or encoding/line-ending changes made while saving remain dirty and recoverable. Failed saves never clear dirty state or recovery. Save-and-close awaits success and leaves the tab open if newer edits remain. Save As prepares immutable bytes before opening the native picker, validates the exported copy, and uses the same adoption path. Its filename suggestion now follows the selected language; its name-field label explains the native picker's hidden-extension behavior. The byte exporter preserves existing text-file extensions instead of forcing unsupported suffixes to `.txt`. Local-file subtitles use “On My iPhone” on iPhone, correcting a hard-coded iPad label found during native interaction.

2. **Split editing and undo — confirmed defects.** Synchronization previously ran before edits were accepted and missed undo, batch replacement, indentation, and line moves. Completed native edits now carry their actual UTF-16 range/replacement to the other pane. Mirroring preserves raw line endings, bypasses input interpretation and duplicate undo registration, and maintains passive selection. Both panes use one undo history and remain mounted across split orientation changes. A batch-undo regression exposed invalid inverse-group closure; `TimedUndoManager` now leaves Foundation's undo/redo group intact. Numbered-list continuation also handles `Int.max` without overflow.

3. **Stale tasks, duplicate state propagation, and focus — confirmed defects and structural problems.** Debounced snapshots could outlive their native view or overwrite a newer load. They now verify view ownership and the last external snapshot, use weak captures, and flush/cancel on teardown or replacement. Closed tabs cancel their pending work; detached tabs keep it. Canceled autosave/spelling tasks no longer clear a replacement task's handle. Superseded opening and delayed navigation/folding callbacks cannot publish into another request. Equal-value text/selection writes were removed. Split-aware focus routing keeps commands on the selected pane. Window chrome preserves that focus, and presented sheets remain associated with their owner.

   Recreating a focused sheet-presenter closure during view evaluation caused UIKit observation-feedback warnings and slow startup. Removing that redundant focused value and routing commands through the existing focused session eliminated the warnings in subsequent full iPad runs. A debugger breakpoint/backtrace and controlled removal isolated this cause; this was more than a formatting change.

4. **Search and replacement — confirmed correctness and responsiveness defects.** Results previously used mutable query settings and could replace content changed since the search. Each search now captures its context, source-window owner, generation, and per-source SHA-256 fingerprint. Replacement consumes only the displayed ranges and searched pattern, rejects changed sources, and preserves regex lookaround context by matching against the original string. Open-buffer replacements use native undo. Folder writes are coordinated and asynchronous, retain encoding/BOMs, protect dirty copies in every window, and report partial successes with per-file failures. Clean matching copies are updated; edits made during a pending write remain protected by their older baseline.

   Duplicate bulk replacement loops were consolidated. Scope/query changes cancel and invalidate old results. Traversal/read errors and skipped oversized files are visible, as are result/file limits; they no longer resemble a complete search with no matches. File and folder insertion use bounded background reads and revalidate the originating document revision and selection before inserting. Inspector metadata no longer performs disk reads during SwiftUI body evaluation.

5. **Window routing and picker ownership — structural problems with correctness consequences.** Typed `EditorRoute` values now carry each URL, line, new-window identity, tab transfer, or restoration record. Utility requests carry their owning session and launch. This replaces the process-global pending URL/line/tab-transfer fields and the utility-request consumption set. Moving a tab keeps it in its source until the destination claims it. Restoration claims records by identity, so out-of-order scene creation cannot swap records. The five-second cold-launch scene-destruction heuristic was removed. Each session owns its picker intent; callbacks retain immutable origin information and explicit cancellation clears the presentation. The unused `DocumentPickerBridge`, snapshot box, and synchronous main-queue exporter bridge were deleted.

6. **Preview, outline, and revisions — confirmed ownership/consistency defects.** Preview retains its originating document, observes source changes, cancels obsolete rendering, and exports immutable HTML. The focus poller and shared temporary export file are gone. WKWebView failures have a visible retry path; reloads retain scroll position and zoom. The sidebar also takes its owning document explicitly. Sidebar, inspector, folding, and preview share heading/fence rules, including LF/CR/CRLF, literal trailing hashes, empty/tab-separated ATX headings, single-line Setext headings, and code-fence exclusion. Footnote extraction leaves fenced examples intact. Zero-result outline filtering remains editable. Revision manifests preserve subsecond timestamps and still decode legacy ISO 8601 manifests, preventing ambiguous rapid-history eviction order.

**Simplification and proportionality.** Removed code includes duplicate heading parsers, separate split-view construction, duplicate save completion, the synchronous document loader/save APIs, unused bulk-close methods, redundant pinning paths, the `autoSnapshot` alias, old cloud-download polling, global one-shot window intents, the unused picker bridge, the focused sheet presenter, export synchronization wrappers, preview polling/temp files, and repeated escape decoding. Escape handling now uses lookup tables and one hex-decoding path. No dependency, generic service framework, or replacement text/rendering engine was added. The small coordinated-access wrapper has one concrete purpose; its unchecked Sendable claim is documented around its lock and Foundation's cancellation contract.

Production Swift has 1,559 added and 1,842 removed lines, including new source files: 283 fewer net. Tests and this report are additional. Line count is descriptive, not a quality measure.

**Follow-up: crash checkpoints and tab navigation.** The question about abrupt termination exposed two confirmed recovery weaknesses: each edit restarted the 800 ms autosave delay, so continuous typing could postpone a checkpoint indefinitely; `ScratchWriter` also swallowed write errors. The scheduler now keeps one deadline from the first pending edit and captures the current native buffer when it fires. Continued typing produces further checkpoints without requiring a pause. This is a scheduling interval, not a guarantee that storage completes within 800 ms. Source files still change only through explicit Save.

`ScratchWriter` propagates failures. The document publishes only the current write generation's result and owns a persistent recovery-warning banner with Retry Recovery and Save actions. Successful retry or explicit save/discard clears the warning; errors from obsolete writes cannot resurrect it. Atomic writes, exact UTF-8 buffer snapshots, separate per-buffer scratch identities, and source-file protection remain intact. The returned autosave task permits tests to await an actual completed write without guessing a delay. No recovery service, generic scheduling framework, dependency, or second timer was introduced.

Tab navigation includes new-tab, overview, close, and recently-closed actions. The iPad strip is present with one tab and remains available when the customizable toolbar is hidden. A fixed trailing **+** and **Tab Overview** remain reachable as the tab list scrolls; tabs share the available width until their minimum usable width requires scrolling. Selecting a tab scrolls it into view. Plus opens a blank tab; its long-press menu retains templates and recently closed tabs. The redundant toolbar New button was removed, and the palette now says New Tab. The overview retains previews, selection, closing, and Done, and supports the same drop behavior as the strip.

One `EditorSession.acceptTabDrop` replaces the strip's two overlapping drop handlers and serves overview drops. It transfers the original document and editor state, preserving undo history and the pinned/unpinned partition. Unknown drops are rejected. New tabs leave their own window's overview synchronously. The switcher's delayed global-focus New and Template tasks were removed; recently-closed actions claim the originating window before starting their existing asynchronous restoration. Obsolete matched-geometry parameters, namespace, ID helper, wrapper, and constant closeability flags were removed. Hidden editor controls are excluded from accessibility while the overview is open. Closing an unsaved preview returns to the editor's existing confirmation; a canceled swipe does not leave an off-screen card.
